# Deploying to Cloudflare Pages

Nothing here has been deployed, committed, or pushed. No git repo was initialised
and no Cloudflare project was created — that is all yours to do when you're ready.

## Cloudflare Pages settings

| Setting | Value |
|---|---|
| Framework preset | Astro |
| Build command | `npm run build` |
| Build output directory | `dist` |
| Node version | 20 or newer (built and tested on 24.18) |

Set `NODE_VERSION` to `20` in the Pages environment variables if the default
image is older.

## Local commands

```bash
npm install
npm run dev        # http://localhost:4321
npm run build      # static output into dist/
npm run preview    # serve the built output
```

## Verification harness

`scripts/verify.mjs` drives the locally-installed Edge over CDP and checks
responsive overflow, reduced-motion parity, keyboard order, contrast (axe-core)
and console cleanliness. Run it against a build:

```bash
npm run preview
```

Then, in a second terminal:

```bash
node scripts/verify.mjs http://localhost:4321 ./verify-out
```

Screenshots and `report.json` land in `verify-out/`.

Two narrower probes sit alongside it:

- `scripts/diagnose.mjs` — confirms counters and scramble effects settle on
  their true values rather than freezing mid-animation.
- `scripts/csp-check.mjs` — serves `dist/` and reports any Content-Security-Policy
  violation. **Run this after any change to `astro.config.mjs` or to how scripts
  are loaded.** The CSP is generated by Astro as a `<meta>` tag with a per-build
  hash for every inline script; a policy that blocks your own bundle looks fine
  in `astro dev` and breaks only in production.

All three are dev-only (`puppeteer-core` and `axe-core` are devDependencies) and
are not part of the deployed bundle. They drive the Edge install at
`C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe` — change the
`EDGE` constant at the top of each if that path differs on another machine.

## Stack notes

Astro 7 + Tailwind v4, with **no UI framework**. GSAP + ScrollTrigger drive the
scroll choreography, Lenis the smooth scrolling, OGL the hero shader.

The cursor and hero backdrop were briefly React islands; carrying React for two
components that only used `useEffect`/`useRef` cost 187 KB of runtime — about
half the page's JavaScript. They are plain Astro components with vanilla scripts
now. Total shipped JS is ~198 KB uncompressed, most of it GSAP.

Do not add a UI framework integration back without checking what it costs here.

## Editing content

All copy lives in YAML under `src/content/` and is schema-validated at build
time, so a typo in a field name fails the build rather than shipping a blank
section.

| Section | Files |
|---|---|
| Experience | `src/content/experience/*.yaml` |
| Tooling | `src/content/tools/*.yaml` |
| Credentials | `src/content/credentials/*.yaml` |
| Earlier career | `src/content/earlier/*.yaml` |
| Metrics | `src/data/metrics.ts` |
| Capabilities | `src/data/capabilities.ts` |
| Design archive | `src/data/archive.ts` |
| Name, email, links | `src/config/site.ts` |

Design tokens — every colour, font and easing curve — are in
`src/styles/theme.css`. There are no hardcoded hex values anywhere else.

## SEO

Everything is in place: title, description, canonical, Open Graph, Twitter card,
`robots`, JSON-LD `Person` schema, a single `<h1>` with clean heading order, alt
text on every meaningful image (decorative gallery thumbnails carry `alt=""` +
`aria-hidden`), `robots.txt`, and a sitemap.

**`site` in `astro.config.mjs` drives all of it.** The canonical URL, the OG and
Twitter image URLs, `robots.txt` and the sitemap are all derived from it —
nothing hardcodes the domain. Change it once when the final URL is known and
redeploy; leave it wrong and search engines and link previews will all point at
the old address.

### The share card

`public/og.png` (1200×630 at 2× = 2400×1260) is generated, not hand-drawn:

```bash
node scripts/make-og.mjs
```

It renders an HTML card with the real typefaces and palette through headless
Edge, so it stays consistent if the brand changes. **Commit the output** — the
build does not regenerate it. Re-run the script after changing the name, roles,
or headline metrics on the card.

This existed as a bug first: `og:image` pointed at `/og.png` before the file
did, which meant every LinkedIn and Slack share rendered a blank preview.

### robots.txt

Generated by `src/pages/robots.txt.ts` rather than kept as a static file, so the
`Sitemap:` line tracks `site` automatically. Nothing is disallowed on purpose —
in particular **do not add `Disallow: /_astro/`**. That folder holds the CSS and
JS; Googlebot renders the page before indexing, so blocking it stops Google
seeing the real layout, and it would hide the archive imagery from Google Images
too.

## Theming

The page follows the device's light/dark setting on first visit. The toggle in
the top-right overrides it, and once a visitor chooses, that choice is stored
and the OS is no longer consulted.

Both palettes live in `src/styles/theme.css`. Light is the base in `@theme`
(Tailwind needs concrete values there to generate utilities); dark overrides the
same custom properties, applied twice on purpose — via
`@media (prefers-color-scheme: dark)` so it is correct with JS disabled, and via
`:root[data-theme="dark"]` so an explicit choice wins.

**The accent is two tokens, and this matters if you change it:**

| Token | Behaviour |
|---|---|
| `--color-accent` | Theme-aware. Lime `#c8f751` on dark, deep olive `#56731a` on light. Text, borders, ticks, dots. |
| `--color-accent-solid` | Constant lime. **Backgrounds only.** |
| `--color-on-accent` | Constant near-black. The text that sits on that fill. |

Acid lime measures about 1.4:1 as text on white — unreadable. The split keeps
the brand colour present in both themes (the CTA is lime either way) without
asking it to carry contrast it cannot carry. If you pick a new accent, check it
against **both** backgrounds before committing, and re-run `scripts/verify.mjs`,
which audits contrast in each theme separately.

The hero shader carries its own per-theme palette in
`src/components/hero/HeroBackdrop.astro` (`PALETTES`) and repaints on a
`themechange` event — light-grey dots would be invisible on a light background,
so they invert.

## Archive gallery

Clicking any archive card opens a native `<dialog>` showing one piece at a time
at full stage size, with prev/next arrows, arrow-key navigation, a thumbnail
strip and a counter. Hovering across a card still scrubs through the same images
in place — both mechanisms are live.

One-at-a-time rather than a scrolling column: these are logos, posters and
mockups, things you look *at*, and giving each the full stage beats scrolling
past a stack of cramped thumbnails.

`<dialog>` was chosen over a custom modal because focus trapping, Esc-to-close,
page inertness and top-layer stacking are all correct for free. Four things are
wired manually, and every one of them was a bug first:

- **`margin: auto` is restored in plain CSS** (`.archive-dialog` in the
  component's `<style>` block). Tailwind's preflight resets `margin: 0` on every
  element *including `<dialog>`*, which silently destroys the UA stylesheet rule
  that is the only thing centring a modal dialog. Without it the gallery pins to
  the top-left corner and runs off the bottom of the screen.
- **The stage uses `min-h-0`.** A flex child will not shrink below its content
  size by default, so the image pushed the dialog past its own height and
  produced two nested scrollbars. The dialog itself must never scroll.
- **Backdrop-click detection checks `event.detail`.** Activating a button with
  Enter or Space fires a click reporting `clientX/clientY` of `0,0`, which falls
  outside the dialog rect and reads as a backdrop hit — so a keyboard user
  pressing Enter on "next" closed the gallery instead of advancing it.
- **Lenis is stopped and the custom cursor released** on open. Otherwise the
  page scrolls underneath the modal, and the cursor — a `z-[9999]` element —
  ends up *behind* the top layer while `cursor: none` is still applied, leaving
  no visible cursor at all. The `close` event restores both and returns focus to
  the card that opened it.

`scripts/verify.mjs` asserts all of this: centring on both axes, fitting the
viewport, zero nested scrollers, next/prev/arrow-key/thumbnail/wrap-around
navigation, survival of keyboard activation, focus restoration, and the same
checks again at 375px.
